# Детализированный Roadmap для MicroSaaS "ContentFlow"

---

## Введение

Этот документ описывает подробный и поэтапный план разработки продукта "ContentFlow". План разбит на функциональные и технологические фазы, от подготовки инфраструктуры до развертывания и документирования готового продукта.

---

### **Фаза 1: Инициализация и Настройка Проекта (Sprint 0)**

**Цель:** Подготовить полную инфраструктуру и среду для разработки, заложить фундамент проекта.

1.  **Система контроля версий:**
    -   Инициализация Git-репозитория.
    -   Настройка веток (main, develop).
2.  **Настройка Backend-стека:**
    -   Создание нового приложения на **Ruby on Rails 8**.
    -   Настройка и подключение базы данных **PostgreSQL**.
    -   Интеграция **Sidekiq** для управления фоновыми задачами.
    -   Установка и настройка **RSpec** для тестирования.
3.  **Настройка Frontend-стека:**
    -   Интеграция с Vite (или другим сборщиком JS) в Rails.
    -   Установка **Shadcn UI** (или его аналога для React/Vue).
    -   Настройка базовой структуры папок для фронтенд-компонентов.
4.  **Среда и Деплой:**
    -   Настройка переменных окружения для `development`, `test`, `production`.
    -   Подготовка Docker-конфигурации (`Dockerfile`, `docker-compose.yml`) для легкого развертывания.
5.  **Документация:**
    -   Создание базового `README.md` с инструкциями по установке и запуску проекта.

---

### **Фаза 2: Разработка Основного Backend (MVP)**

**Цель:** Реализовать всю ключевую серверную логику, необходимую для MVP.

1.  **Аутентификация и пользователи:**
    -   Модель `User` (с использованием гема `Devise`).
    -   API-эндпоинты: `POST /signup`, `POST /login`, `DELETE /logout`.
2.  **Управление проектами (WordPress сайтами):**
    -   Модели `Project` для хранения данных о сайтах.
    -   API-эндпоинты: CRUD для проектов (`/api/v1/projects`).
    -   Реализация логики проверки подключения к WordPress (валидация API ключей).
    -   Шифрование и безопасное хранение ключей доступа.
3.  **Базовое управление подписками:**
    -   Модели `Plan` и `Subscription`.
    -   Интеграция с **Stripe API** (гем `stripe`).
    -   API-эндпоинты для получения тарифов и управления подпиской.
    -   Настройка веб-хуков для обработки событий от Stripe (успешная оплата, отмена).
4.  **Админ-панель (базовая):**
    -   Создание пространства имен (`/admin`).
    -   Реализация базового дашборда для просмотра списка пользователей и их статусов подписки.
5.  **Тестирование:**
    -   Написание юнит- и интеграционных тестов для всех API-эндпоинтов.

---

### **Фаза 3: Документация по Backend API**

**Цель:** Создать понятную и полную документацию по API для frontend-команды.

1.  **Выбор инструмента:**
    -   Интеграция `Rswag` для генерации документации OpenAPI (Swagger).
2.  **Написание спецификаций:**
    -   Детальное описание всех эндпоинтов, параметров запросов и форматов ответов.
    -   Примеры запросов и ответов.
3.  **Публикация документации:**
    -   Настройка роута, по которому будет доступна сгенерированная документация (`/api-docs`).

---

### **Фаза 4: Разработка Frontend (MVP)**

**Цель:** Создать пользовательский интерфейс для всех реализованных backend-функций MVP.

1.  **Основа интерфейса:**
    -   Создание основного лейаута приложения в стиле **Notion** с использованием **Shadcn UI**.
    -   Настройка роутинга на стороне клиента (React Router / Vue Router).
2.  **Аутентификация:**
    -   Формы и страницы для регистрации и входа.
    -   Реализация логики сохранения токена и защиты роутов.
3.  **Дашборд и управление проектами:**
    -   Главная страница со списком проектов пользователя.
    -   Интерфейс для добавления, редактирования и удаления сайтов.
4.  **Управление подписками:**
    -   Страница "Настройки" для управления профилем.
    -   Интеграция **Stripe Elements** для безопасной формы оплаты.
    -   Интерфейс для смены тарифа и отмены подписки.
5.  **Взаимодействие с API:**
    -   Создание сервисного слоя (API client) для взаимодействия с задокументированным Backend API.

---

### **Фаза 5: Разработка и Интеграция AI-логики (Backend Post-MVP)**

**Цель:** Реализовать ключевую интеллектуальную функциональность продукта.

1.  **Анализ ключевых слов:**
    -   Разработка фоновых задач (Sidekiq worker) для анализа тем.
    -   Интеграция с внешними SEO-сервисами (SEMrush, Ahrefs API) или создание собственного парсера.
    -   Реализация алгоритма кластеризации ключевых слов.
2.  **Генерация статей:**
    -   Интеграция с LLM (Gemini/OpenAI API).
    -   Разработка промптов для генерации HTML-статей на основе кластеров.
    -   Модель `GeneratedArticle` для сохранения результатов.
3.  **Интеграция с WordPress:**
    -   Разработка воркера для отправки сгенерированной статьи на сайт пользователя через WordPress REST API.
4.  **Интеграция с Google Services:**
    -   Реализация OAuth2 для подключения аккаунта Google.
    -   Создание сервисов для регулярного сбора данных из Google Analytics и Search Console.

---

### **Фаза 6: Разработка Frontend (Post-MVP)**

**Цель:** Реализовать интерфейс для AI-функций и аналитики.

1.  **Процесс генерации контента:**
    -   UI для запуска генерации статьи из идеи.
    -   Отображение статуса генерации (в процессе, готово, ошибка).
    -   Простой редактор для просмотра и правок сгенерированного HTML.
    -   Кнопки для публикации в WordPress.
2.  **Дашборд аналитики:**
    -   Проектирование и реализация виджетов для отображения данных из GA и GSC.
    -   Создание детализированных страниц аналитики для каждого проекта.

---

### **Фаза 7: Финализация и Комплексная Документация**

**Цель:** Отполировать продукт, подготовить к запуску и создать исчерпывающую документацию.

1.  **Тестирование:**
    -   Написание E2E (End-to-End) тестов.
    -   Проведение UAT (User Acceptance Testing) с фокус-группой.
2.  **Деплой:**
    -   Настройка CI/CD-пайплайна (e.g., GitHub Actions).
    -   Развертывание приложения на хостинге (e.g., Heroku, DigitalOcean, AWS).
3.  **Финальная документация:**
    -   **Руководство пользователя:** Детальные инструкции по использованию всех функций сервиса.
    -   **Руководство разработчика:** Описание архитектуры, процессов, инструкций по развертыванию.
    -   Финализация и публикация **API-документации**.
    -   Обновление **GEMINI.md** и **PRD.md** для отражения финального состояния продукта.
